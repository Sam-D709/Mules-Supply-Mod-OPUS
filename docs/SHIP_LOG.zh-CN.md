# M4 简要调度日志与 Debug

公开测试版：**0.1.0-beta.3 / 内部665**，见[发布说明](releases/v0.1.0-beta.3.md)。采购规则沿用 beta.1；替换 beta.2 的逐候选游戏内报告。

## 为什么调整

存档20中，约42.659秒游戏时间内有5,484条M4详细日志，正文合计5,764,677字符；单份报告达到200页，某个相同时间戳下集中写入884条。候选文字生成、重复拼接、分页写入及原生日志筛选都会增加开销。这是明确的日志膨胀证据，不能代替实时FPS测量。

原生飞船日志是从玩家总日志按飞船编号筛选的视图，不是独立存储。把大量候选记录写入飞船，也会扩大总日志。

## 默认模式：只看结果

在对应船的 **信息 → 日志** 查看 **M4 调度摘要**。无需启动参数。

每次成功提交只生成一条报告，包含：

- 本船、基点、最低装载率、最大采购笔数、基点范围、副单偏离范围、估价加成、自有库存门槛与用途/货源开关。
- 采用正常派单还是尾单解限；解限只对当前评估有效，不永久改动玩家设置。
- 正常评估和尾单评估各自的笔数、体积、容量和装载率。
- 结束组合的原因：满仓、达到笔数上限，或者没有可执行的下一单。
- 真实提交的每笔商品、数量、供应站、收货站与实际单价。草案通过不等于派单成功；失败提交不列为执行中的采购。
- 简要失败统计：价格、偏离范围及其他过滤条件。同型号失败缓存只共享小型数字统计，不复制候选文字。

最终待命时写一条简报，并保留当前具体失败原因。**相同设置、基点与结果阶段10分钟内不重复**；价格、库存等波动不重置冷却。更换设置或成功派单后可重新报告。行为页仍显示当前失败。

## 数字怎样理解

| 统计 | 含义 |
|---|---|
| 价格失败次数 | 实际采购价不低于收货站买价的检查次数；另列其中副单检查次数 |
| 最小价差缺口 | 已拒价格候选中，最小的“实际采购价减收货价”，并列出对应商品。0表示同价，普通NPC采购仍要求正价差；按真实价格检查，不使用偏离加成后的竞争估价 |
| 偏离范围失败次数 | 副单已执行到走廊检查并因超出设定被拒的次数 |
| 最小超出跳数 | 被拒副单中，最小的“实际偏离跳数减玩家允许跳数”，并列出对应商品 |
| 其他过滤次数 | 需求范围、仓型、报价有效性、库存门槛、停靠、无人机或数量等检查触发的排除 |

例如“偏离范围失败12次，最近仍超出1跳”表示当前范围不足以接纳这些已检查货源；“价差缺口3 Cr”表示最接近的那个货源采购价仍高出收货价3 Cr。

这是**首次失败条件的检查次数，不是去重后的工厂数量**。同一货源可能在不同采购位置重复检查。前一关失败就不会额外检查后续条件，因此不能保证单独修改跳数或价格后一定成交；未访问的需求或货源也不包含在统计内。不可达不当成巨大的有限跳数。统计在原有搜索中更新数字，不增加货源、路径或价格查询。

## Debug：详细记录到磁盘

1. 在 Steam 的 X4 启动选项末尾添加 **-scriptlogfiles**，完整退出并重新启动游戏。只添加这个参数即可，不必开启全游戏的调试输出。
2. 游戏中打开 **扩展选项 / Extension Options → Mules-Supply-Mod-OPUS → Debug：详细磁盘日志**。
3. 开启后复现问题，观察新一轮搜索。已有排队订单不能补写历史搜索。
4. 读取文件：

```text
C:\Users\[Windows用户]\Documents\Egosoft\X4\[用户ID]\logs\MulesExtended\debug.txt
```

5. 复现完成后关闭 Debug。文件保留并继续追加，不自动清空。

菜单通过 **SirNukes Mod Support APIs 的公开 Extension Options 接口**注册，与本机 kuertee UI Extensions 共用现有菜单；不改动 kuertee 文件，不新增 Lua 加载器或 Options Helper 依赖。菜单需要 Mod Support APIs，已在本机安装；缺少时默认简要日志与采购仍可运行。开关默认关闭，跟随当前存档保存，不自动应用到其他新存档。

X4原生 debug_to_file 只能写文档目录的游戏 logs 子目录，**不能直接写模组安装目录的debug.txt**。缺少 -scriptlogfiles 时开启菜单开关也不会创建磁盘文件。磁盘受云同步/文档重定向影响时，以实际X4用户目录为准。

Debug 开启后记录逐候选拒绝原因、数量约束、价格比较、固定主路径、主副单选择及提交复核。候选行带船号与阶段，部分船队级消息带基点；同型号复用用 MODEL_SKIP 标识。详细记录直接写文件，不再存成候选文字列表，也不分页写进船只/总日志。关闭时在调用位置跳过详细文字生成。Debug本身仍可能产生大量磁盘写入，只用于复现。

## 从 beta.2 升级

完整退出游戏，备份旧模组目录，安装beta.3后读取存档副本。存档中的旧详细日志仍然保留；本版只清除驾驶员上已废弃的完整报告缓存，不删除玩家日志、存档或现有贸易队列。旧日志已经膨胀时，打开日志页仍可能较慢，可自行通过游戏界面清理。

## 游戏验收

| 编号 | 操作 | 预期 |
|---|---|---|
| L01 | Debug关闭，重现存档20场景 | 只产生派单/冷却简报，不出现候选分页；比较游戏流畅度 |
| L02 | 小额尾单装载不足 | 一条提交摘要同时说明正常不足、尾单解限和真实采购结果 |
| L03 | 副单采购价高于或等于收货价 | 每阶段只有汇总行，缺口与当时实际报价相符；相等也不通过 |
| L04 | 副单在路径外1跳，偏离限制0 | 汇总最小超出1跳；扩大范围后的下一次评估可重新竞争，仍需通过其余条件 |
| L05 | 无法停靠或双方无货运无人机 | 本船行为页与待命简报保留具体失败，解限不能绕过 |
| L06 | 同型号多艘船失败 | 各船至多一条冷却简报，复用统计注明来自代表船 |
| L07 | 待命时反复波动价格/数量 | 不绕过10分钟冷却；成功派单仍每次记录 |
| L08 | 开启Debug并重启后复现 | 正确目录出现debug.txt，可按船号追查；船只日志仍是简要报告 |
| L09 | Debug关闭后继续新搜索 | 新的详细磁盘记录停止；关闭状态随存档保存与重载保留 |
| L10 | 英文界面 | 菜单、摘要与详细原因均为英文，无缺失文本编号 |
| L11 | 加载beta.2已有排队贸易的存档 | 订单保留；旧日志不丢失；下一轮使用新摘要 |

本地测试不模拟真实界面渲染、磁盘刷新、游戏调度或FPS。菜单显示和原生文件落盘需要上述游戏验收。
