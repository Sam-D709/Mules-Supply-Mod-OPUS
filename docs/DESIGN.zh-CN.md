# M4 详细设计与实现说明

本文保留实现细节与限制。参数对照和安装方法见 [README](../README.md)。

## 相比原版的变动表

### M4 调度与采购

| 项目 | 对照原版的行为或问题 | 本基线的行为 | 改动思路 |
|---|---|---|---|
| 调度单位 | 主要由每艘船各自检索、配对报价 | 同一基点共用需求、货源索引与船队成员表，按轮次逐船编排 | 减少相同空间站和货物被每艘船重复发现的工作 |
| 船型优先级 | 没有跨船队、按实际容量统一分配的两阶段机制 | 按实际货仓容量排序，不使用固定 XL→L→M→S 顺序 | XL 不一定比 L 装得多，模组军舰和特殊货船也必须按真实容量判断 |
| 同型号分组 | 同类船容易重复做相同失败搜索 | 以型号、总容量和各运输类型容量等形成兼容组；条件等价时复用本轮失败结果 | 同型号多艘船不必重复证明同一个不可行组合，但仍保留逐船资格检查 |
| 船队更新 | 各船独立处理自身行为 | 注册、站属增减和摧毁事件触发更新；另有 30 秒兜底复核。型号集合/容量改变才重排容量顺序 | 同型号新增一艘主要更新数量，新型号或新容量才需要调整排序 |
| 正常派单 | 以单船报价评分筛选为主 | 从高容量组到低容量组；先在服务范围、货物用途优先桶内比较需求体积 | 让大船优先处理适合大货仓的缺口，同时保留基点和建造材料等优先级 |
| 尾单递补 | 普通小额需求可能长期低于最低装载比例 | 正常阶段结束后，从低容量组到高容量组豁免装载率，继续分配剩余合法需求 | 小船忙了，中船可以接手；只有一艘小船时，大船不会永远旁观 |
| 多笔采购 | 上游保留了将已有 M4 最大交易数改为 1 的旧迁移补丁，多单存在旧路径和编排问题 | 每趟默认最多 3 笔，可设 1～10；先排全部采购，再排全部交付 | 在出发前检查整趟方案，避免买一笔送一笔或不同报价/数量配错 |
| 装载率 | 普通小单易被门槛挡住；原滑块最低 25% | 滑块允许 0～95%，默认 75%；按整趟组合体积判断，尾单阶段可豁免 | 不能因为只缺 1 件、15 件，就永久无法补齐 |
| 每笔最小比例 | 原说明按最大交易次数推导每笔最小载货量 | 最大笔数控制整趟采购次数，装载率控制整趟组合体积 | 小副单也可以参与拼单，不要求每笔都占固定货仓比例 |
| 多厂凑货 | 原单船配对不提供新的共享多厂编排机制 | 同商品可以从不同供应站形成不同采购笔数；每个报价在一份草案中最多使用一次 | 最近工厂产量不足时，沿允许范围补足，不假设一个供应站能满足整个缺口 |
| 重复接单 | 原生预订和船间独立检索需要协调 | 从游戏净报价数量出发，只为尚未反映到游戏预订的提交部分临时占额 | 同一笔运输不能既被游戏扣掉，又被模组重复扣一次 |
| 提交一致性 | 逐笔创建时可能出现前后状态变化 | 提交前复核所有报价、累计资金、共享仓容、预订数量和配置；局部失败仅撤销可撤销的新排队订单 | 在真实经济写入前检查整趟计划，保留已经运行的订单 |
| 取消后重派 | 主要等待单船重新搜索 | 取消事件提前唤醒基点，净数量核算清理失效占额 | 一艘船的取消不应让其他船误以为需求仍被占用 |
| 站属分配 | 默认行为与指挥官变更可能导致订单被接管；本地测试中也出现过绑定记录缺失 | 修正初始化和迁移后的站属绑定，保留 M4 默认行为；玩家手动解除原绑定后，不强制重新拉回 | 站属关系用于管理便利，不应破坏自定义采购行为 |

### 货源、价格和界面

| 项目 | 对照原版的行为或问题 | 本基线的行为 | 改动思路 |
|---|---|---|---|
| 主单货源 | 原逻辑侧重估算收益等评分 | 对已选定主需求，先比较供应站距基点的合法跳数，同跳数再比较实际采购价 | 采购优先补货效率，避免为了稍低价格无限延长主运输距离 |
| 副单搜索 | 旧多单没有当前固定主路径及偏离估价机制 | 固定 H→主单货源 A 的路径；限制副单偏离跳数，以距离加成价竞争同商品货源 | 减少拼单造成的大幅绕路，并给玩家明确的范围和成本偏好 |
| 实际优惠 | 直接使用 `unitprice` 会遗漏玩家享有的部分实际优惠 | 调用带实际交易船的原版价格过滤，估计优惠/佣金后的价格；提交前重查 | 同距离货源竞争、副单估价、价差合法性和预算使用一致的价格口径 |
| 自有货源开关 | 原有玩家货源开关与“玩家购买模式”估价百分比配合使用 | 开关改为“启用从玩家工厂进货” | 用明确的进货权限表达玩家意图 |
| 玩家购买模式 | 对自有卖价乘百分比，含义难懂，且不能表达工厂应何时转向内部供货 | 删除可见旧参数，改为“玩家工厂存货超过%时允许供货”，默认 50% | 销路好、库存低的工厂继续对外销售；积货或专供工厂才参与后勤 |
| 自有内部调拨 | 估价修正与利润判断耦合 | 合法自有货源通过库存门槛后，不要求买卖价差为正；原版免费取货按零成本比较 | 后勤可以为研究和造船运货，不必制造账面利润 |
| 允许商品 | 纯贸易库存受单独开关控制 | 删除可见开关，按合法买报价给纯贸易库存补货 | 玩家已经在站里设置买卖报价，就不需要再勾一个模糊的“商品”开关 |
| 用途翻译 | “原材料”“中间产物”“允许建材”容易被理解成货源类型 | 改为“为建造仓采购材料”“采购本站不生产的消耗物资”“采购本站自产自用的物资” | 说明这是按收货对象的用途分类，不是只购买矿石/气体或从建造仓取货 |
| 搜索计算强度 | 用户调百分比；旧抽样还可能把小列表截成零条 | 删除可见参数，固定完整候选遍历和分批让出机制 | 维护优化由调度器负责，玩家无需在“不接单”和“性能”之间猜滑块 |
| 余货处理 | 原版提供删除货物并按均价补偿的虚拟清仓路径 | 本基线明确用于无任何活动/排队订单的船，按实际删除数量补偿个人账户 | 避免退货失败造成复杂恢复链；不得清掉正常在途货物 |
| 失败原因 | 总日志和内部字段不便按船定位 | 中文原因和相关数值；基点警报、逐船磁盘诊断，以及该船行为页的失败提示 | 明确区分无人机、泊位、价格、库存、距离、资金等不同原因 |
| 空闲返航 | 没有本基线的同基点整队空闲返航机制 | 同一基点有效 M4 全部空闲时，返回基点站所在区域或基点星区 | 空闲船靠近下一轮工作的起点，避免一直停留在远处供应站 |

## M4 的调度思路

### 1. 先把船按实际能力放到一起

同一基点的 M4 成员登记到共享表。分组不仅看显示型号，还看实际总容量和集装、固体、液体等运输能力，避免把“型号相同、容量或可运输类型却不同”的船当成完全等价。

正常阶段从大容量向小容量派单；仍有合法需求时，尾单阶段反过来，从小到大豁免装载率。豁免只放宽装载率，**不放宽最大笔数、货源权限、预算、仓容、停靠、无人机、距离和贸易规则**。

例如 90,000 容量大船、30,000 容量中船和一艘 5,000 容量小船都无法用最多三单达到 75%：尾单阶段先给小船任务；它已经忙碌后，剩余需求可以继续派给中船、大船，不用等小船送完回来。

每船最多三笔时，十种各缺 1 件的合法需求可以由约四艘船分担，而不会因为一艘船能装下，就把全部十笔需求塞给它。实际分配还取决于收货对象、货物运输类型及各船资格。

### 2. 需求按用途和服务范围排序

先按基点、本星区、允许扩展的服务范围分层，再按建造仓、生产消耗、自产自用、纯贸易库存分类。同一层级内部比较缺口体积 `净需求数量 × 单件体积`，不是按商品件数或总价值把所有需求混在一起排序。

因此，“大单优先大船”不意味着远处昂贵商品可以无条件压过基点的建造材料。每趟只选择一个收货对象；当前实现还约束组合货物使用同一运输类型。

| 基点与设置 | 送货对象 | 货源范围 |
|---|---|---|
| 玩家站，开启“仅服务基点” | 该站及符合条件的建造仓 | 基点活动范围内允许的玩家/NPC 供应站 |
| 星区，开启“仅服务基点” | 该星区的玩家站 | 基点活动范围内允许的玩家/NPC 供应站 |
| 玩家站或星区，关闭“仅服务基点” | 依次考虑基点、本星区及范围内其他玩家站 | 同上 |
| 明确选择 NPC 站 | 按 NPC 基点规则服务该站，允许扩展时考虑本星区 NPC | 仍受货源开关与贸易合法性限制 |

### 3. 主单优先近，副单限制绕路

主需求确定后，货源先比较从基点出发的合法星区跳数，同跳数比较实际价格。这里的“距离”是跳数，不是精确飞行时间，也不是当前船位置到供应站的秒数。

主单供应站 A 确定后，固定基点 H→A 的合法路径作为本趟走廊。后续副单不会把这个走廊越扩越远，且始终同时受基点最大活动范围限制。

```text
副单供应站的偏离距离 d = 该星区到主路径任一星区的最小合法跳数
竞争估价 = 实际采购单价 × (1 + d × 每跳加成 / 100)
```

默认副单偏离范围 2 跳、每跳加成 5%。同商品的主路径报价为 103，偏离一跳的报价为 100 时，后者估价为 105，因而选择 103 的路径内货源。若只有偏离一跳的那个合法货源，加成不会凭空产生一个竞争报价，也不会把 105 当成真实收费；它仍可入选。真实价格合法性继续使用实际报价判断。

每跳加成设为 0，仅取消价格惩罚，**不会取消副单偏离范围或基点范围**。副单估价相同，才进一步比较相对上一采购站的绕路量。当前是贪心组合，不保证找到所有可能组合中的全局最优路线。

### 4. 自有库存是参与门槛，不是保留库存

```text
自有供应站允许参与 ⇔ 该商品实物库存 × 100 > 该商品分配仓储量 × 门槛百分比
```

严格超过才参与，分配量为零时跳过。判断基于该站该商品的分配量，不是整站总货仓。

分配 10,000、库存 8,000、门槛 60%、目的地需要 7,000 时，可以搬走 7,000，留下 1,000。门槛用于决定本次能否把这个站当作货源，并不要求搬完后仍保留 60%。派单及提交前均检查，已提交的运输不因库存随后下降而被取消。

这表达的是：库存低、销售顺畅的工厂主要赚钱；积货或玩家专门留作供应的工厂参与后勤。它不会永久标记工厂用途，也不会修改该站卖给 NPC 的价格。

开关和门槛也不会强制选择更远的自有工厂。所有合格货源仍按主单距离规则竞争；同跳数时，原版允许免费取货的自有来源按零成本比较。合法出售报价、可售数量和贸易权限始终需要存在。

### 5. 真实报价、预订和提交分别处理

报价的 `amount` 已经包含游戏原生预订的影响。模组临时占额只补上“新订单已创建、游戏报价暂时还没反映”的差额；一旦原生预订接管，就清掉对应模组占额。不会简单地把所有在途数量再减一遍。

价格方面，无优惠时直接使用报价。有优惠/佣金时，通过原版带 `tradepartner` 的价格过滤做有界查询，精度为 0.01 Cr、每次求价最多 33 次过滤查询；结果在当前调度轮内缓存。提交前重新读取，避免优惠失效或价格变化后还使用旧草案。查询不会创建试探交易，也不会为估价占用货源。

普通 NPC 外购仍要求收货买价高于实际采购价；自有调拨和符合条件的专用玩家建造仓模式有相应例外。因此“有需求、有货源”不必然等于存在合法可执行采购。

## 性能设计与实际边界

| 机制 | 当前实现 | 解决的问题与边界 |
|---|---|---|
| 共享需求/货源索引 | 以基点共用需求表；货源索引为商品→星区→空间站→报价 | 避免每船全量发现；没有维护一份对所有船都适用的永久距离排序，船的黑名单可能不同 |
| 发现报价增量插入 | 新发现报价插入对应商品/星区/供应站桶 | 新贸易站不需要每艘船重新建立全部索引 |
| 事件与兜底刷新 | 成员、生产、贸易、取消等事件唤醒；共享发现与成员复核另有 30 秒周期 | 并非所有仓储/全局设置编辑都有专门事件监听 |
| 同型号失败复用 | 本轮内按容量组、配置、资金、指挥官、无人机和个人黑名单等条件建立失败键 | 有个人黑名单的船使用船自身隔离；成功提交后清空本轮失败缓存 |
| 路径缓存 | 一份草案内按供应站星区复用偏离走廊的计算 | 固定主路径，让同星区不同商品共享计算 |
| 分批让出 | 每 20 次货源检查、128 次需求/索引操作、16 次成员遍历等位置让出 | 不丢弃候选；但一次原生大范围发现查询本身仍可能有开销 |
| 提交串行 | 跨基点的共享锁保护派单与经济提交；长循环让出时刷新锁时间，异常锁有超时恢复 | 防止两个基点同时争用同一货源；不同基点也可能互相等待计算完成 |
| 空闲退避 | 无成功派单时逐步退避，上限 30 秒；事件可提前唤醒 | 没有需求时仍保留轻量复查，并非完全关闭搜索 |
| 空闲返航 | 原版移动子脚本配合每段最多 30 秒的带身份延迟信号 | 飞行期间不由本船持有调度锁，不创建永久等待队列挡住下一轮采购 |

船更多，成员遍历、资格检查、订单、日志和原生飞行仍会增加成本。共享索引与失败复用只能减少重复部分，不能承诺 200 艘 S 船或 XL/L/M 混合船队完全不卡，也不能把串行派单理解为总计算量不随船数增长。当前没有这两类规模的实际 FPS 基准。

详细逐候选日志按本项目调试需求保留，尚未默认关闭。大范围、高船数和大量优惠报价共同出现时，尤其需要实际性能测试。

## 空闲、日志与余货

**返航条件：** 同一基点的有效 M4 全部空闲。其他成员仍执行贸易、有手动命令或由玩家驾驶时，不启动新的整队返航；已取消 M4、被摧毁或从原绑定脱离的成员不算在内。站基点返回该站所在区域附近，不占贸易泊位；星区基点进入该星区即可。回程遵守旅行黑名单，无法返回时留下本船诊断并继续后续搜索。

**船上查看原因：** 选中该船，进入“信息 → 行为”，查看默认行为的失败提示。这是原版行为失败记录，不是财务交易历史。提示包含船名/编号、基点和本轮最后一个实际排除原因；成功接单或已无匹配需求时清除。不同候选可能失败于不同原因，不能把“最后原因”当作完整归因。

**总日志：** 未满足需求的基点警报继续保留，同一需求通常间隔 10 分钟记录，弹出通知另有 30 秒合并节流。

**磁盘诊断：** 以 `-scriptlogfiles` 启动游戏后，在游戏日志目录的 `MulesExtended` 子目录查看 `M4 Capacity Dispatch`、`M4 Capacity Candidates`、`M4 Capacity Accounting` 和 `M4 Ship <船编号>` 文件。逐船同原因最多每 10 分钟补写，原因改变立即写入。游戏内行为提示不需要这个启动参数。

**虚拟清仓：** 无任何活动或排队订单的船轮到派单时，如有余货，会删除货物并按实际删除件数×商品定义均价补偿玩家个人账户。这不是向空间站交货，不恢复研究进度；也不是按原采购价退钱。它会处理手动装入的无订单货物，使用前应理解这一取舍。正常采购后等待交付的货物有订单保护，不进入此路径。

## 保留规则与已知限制

- M4 不按“军舰”类别排除船。仍需可运输对应货物、兼容贸易泊位；大船与交易站双方都没有货运无人机时不能装卸。
- M4 使用 civilian 民用黑名单组，并传入实际船只。它没有全面监听玩家“全局命令”页面所有规则修改的事件，也不保证已经交给原版的在途订单立即按新规则重规划。
- 当前模仿桥接已传递副单范围/加成和原有参数，但**尚未显式传递新增的 `playerStockThreshold`**。模仿调用可能使用默认 50%；需要其他门槛时，优先给各船直接配置 M4。这项边界没有在本次发布整理中改写代码。
- 主单按跳数优先，不是精确用时最优；副单为固定走廊内的贪心组合，不是全局最短路径求解器。
- M4 根据合法买报价采购，不单独把研究所需件数当作唯一目标，也不重写原版自动分配仓储和自动定价。因此研究已足够、但买报价仍很大时，仍可能有采购需求；需从空间站自身报价设置调整。
- M4 不主动为所有空间站添加任意商品买卖报价。M2 的“将目标设为贸易仓库”等原有功能仍可能添加贸易商品；已有商品不会因关闭该开关自动删除。
- 删除“允许商品”不等于解除所有最终产品过滤；收货站只生产、不消耗的最终产品仍保留原有特殊过滤。
- 当前内部还保留旧参数、迁移补丁和未进入新 M4 主流程的继承代码，以兼容已有订单。它们不是旧版本安装包，也不表示可见界面仍启用这些旧选项。
- 主要文档及新诊断提供中文和默认英文；其他语言资源沿用上游，并非全部重新翻译。
