# M4 详细设计与实现说明

适用于本地测试版beta.7/内部669，旧发布说明仅描述对应历史版本。

## 详细算法介绍

每艘空闲 M4 独立找单，使用同一基点共享的需求和货源索引。船型和货仓容量影响能装多少、能否满足装载率，不再规定大船先处理完、小船才能接单。谁先完成合法方案并成功提交，谁取得相应数量。

### beta.7 分级与限额修复

主单按兼容空闲船的实际仓容分档，档内最大/最小不超过1.5倍。使用本船合法候选的净需求/净供货估算体积，同收货对象、同仓型可组合供大船处理；副单跨档补舱。等待90游戏秒或3轮未获任务后允许跨档主单，不设全船队先大后小屏障。分级是软优先，最终资格与路线仍逐船验证。

未获任务满2/5/10游戏分钟时，有效装载率上限分别降为50%/25%/0%；原设置更低时沿用原设置，三次完整装载失败仍可提前豁免。只成功派单或更换配置才重置等待起点，预算耗尽和返航不重置。

净供需缩水后仅修复一次，按最新数量重建原单，从已有候选额外检查最多12个、补最多2笔，再通过有效装载率与全部最终复核。不会为修复重新发现全宇宙报价。共享粗筛只保存基点/商品的原始货量、距离、报价排序，30游戏秒到期或发现变化时更新；个人资格和失败不共享。

返航的30秒信号改为调用专用优先级1的poll脚本，保留无任务时的移动栈；原生遇袭响应优先级10仍可阻止本次搜索，随后信号继续重试。详见[beta.7说明](releases/v0.1.0-beta.7.md)。

### 货量与航程怎样取舍

采购数量来自实际可用卖报价，而非工厂全部实物库存：先扣除原生预订尚未接管的模组占额，再限制于净需求、船仓、收货仓、双方资金和最小交易量。货物体积使用游戏的 `ware.volume`，运量为 `数量 × 单件体积`。

对每种商品，保留货量大、距基点近、原始报价低的少量货源，以及自有优先与轮换候选。实际船只资格、优惠和净数量只对这些候选检查。失败后扩大候选并轮换，避免永远盯住同一批不适用工厂。

主单可以替换，不由最近一家少量补产的工厂永久决定。尝试有限的主单与多笔组合，先判断是否达到最低装载率，再比较自有供货占容量比例（仅开启优先时），随后比较：

```text
方案效率 = 整趟实际可交付体积 / 预计整趟耗时
预计耗时 = 船当前位置→各采购点→收货站的合法跳数权重 + 每次装卸权重
```

当前按 S/M 每跳90、每次装卸45，L/XL 每跳180、每次装卸120估算相对时间。这是调度启发值，不是游戏原生ETA；尚不含星区内距离、拥堵、实际航速或真实泊位等待。相同等级的方案再以累计实际价格和偏离加成成本比较。

| 情况 | 预期取舍 |
|---|---|
| 最近工厂只有10件，稍远工厂能装满 | 少量货源不会自动锁定主单；比较更完整的方案 |
| 附近能装80%，远处能装100%，门槛75% | 两者都可出发，再按预计单位时间运量比较；不强求满载 |
| 两种需求分别只能装40% | 同收货对象、同仓型、路径允许时可组合为80% |
| 同种商品分散在两家工厂 | 可以分别采购，分别计入最大采购笔数 |
| 价格更低但明显绕远 | 折扣不自动压过运输效率，预算和价差仍必须合法 |

### 多单与有限搜索

每趟服务一个收货对象、使用一种兼容仓型，先全部采购再交付。基点/本星区/扩展范围以及建造仓/消耗/自产自用/贸易库存仍有优先层级；副单可组合其他允许用途的货物。每个主单方案都有独立的“基点→主货源”固定走廊，副单不得突破走廊或基点最大范围。

每次最多192次需求与货源配对检查、128次路线扩展；每个状态最多选择6个扩展候选、保留3个方案。达到上限后继续轮换需求和货源，下一次再找，不把搜索不完整计为装载不足。候选筛选额度与路线扩展额度独立：筛选耗尽仍可用已找到的候选拼单。组合前刷新净供需，每次有限扩展再次读取净数量，减少搜索让出后沿用旧满仓数量的情况；最终提交仍复核。这是有限搜索，不保证全局最优；最大采购笔数是上限，不要求每次凑满。

### 三次装载不足后放宽

本船连续三次**完整搜索**只有低于最低装载率的方案，第四次搜索临时豁免装载率。价格、权限等其他失败会打断连续计数；计算额度耗尽不增加计数。成功或更换配置后重置。只放宽装载率，资金、报价、路径、仓容、无人机和最大采购笔数仍有效。

### 共享索引与短提交锁

先在共享发现阶段排除不属于服务对象的NPC买单。新发现报价可增量加入索引，另有30游戏秒刷新；刷新期间发生新增报价会要求后续重建。各船搜索可交错运行。

全局互斥只保护最后的净数量复核、占额及订单创建，临界区及其助手均使用非阻塞动作库；不覆盖发现报价、规划路线或整支船队。提交前重新读取实际价格，变化后只要仍符合预算和价差就可提交，避免自有站报价变化让合法运输反复作废。

### 玩家工厂库存门槛

自有货源须满足 `该商品库存×100 > 该商品分配仓储量×门槛百分比`。分配量为零或恰等于门槛时跳过。默认50%；这是参与条件，运输后无需保留该比例。关闭自有优先仍允许合格自有供货，与NPC按普通规则竞争；NPC开关独立。

## 文件职责

| 文件 | 职责 |
|---|---|
| `mule.fleet.run` | 读取当前配置、登记成员、保留绑定及返航流程；迁移旧长循环 |
| `mule.fleet.wave` | 逐船失败计数、退避、共享发现构建及本船提交；成功收尾由commit完成 |
| `mule.fleet.scope` / `discover` | 先排除无关收货对象，按商品/星区/供应站共享索引 |
| `mule.fleet.plan` / `candidate` / `extend` | 有限候选、单船真实资格检查及多单组合搜索 |
| `mule.fleet.commit` / `net` | 提交前价格和余量复核、短锁、临时占额与原生订单交接 |
| `md/mwex_capacity` | 报价发现、加载清理和成员事件；空基点回收索引，不再维护容量队列 |

## 取舍与性能边界

候选查价、净数量及资格仅在本次单船搜索内缓存；不跨船复用失败，以免资格不同导致误判。共享的是收货对象、报价索引和短期粗排序，不是对每艘船都适用的永久合法路径排序。原始报价和需求排序仍随市场规模增长，遇到长循环每128项让出；并非所有运算都具有常数上限。昂贵配对和路线扩展有固定额度。

当前无精确ETA；供应商截取以原始价格为一个线索，实际折扣由候选阶段读取，因此尚未入选的优惠供应商可能需轮换后才能找到。不同主单各有固定走廊，副单不能不断扩张走廊。

共享发现构建有单独归属和心跳；旧索引可继续使用。发现期间新增报价标记需再刷新，过期构建不能覆盖替代构建。刷新仍需一次原生范围发现调用，不保证它无性能开销。

临时占额仅扣除尚未被原生预订接管的差额。原生`run_script`本身是阻塞动作，不能由“没有显式wait”推导不会让出。beta.6把net、trace、scope、offer、price、candidate、extend、summary、journal、report统一为10个命名动作库；beta.7增加sources、grade、repair，合计13个。使用`include_interrupt_actions`直接在调用者作用域执行；输入、输出和临时量有各自前缀，输出每次重置。旧脚本入口仅作存档和工具兼容包装，不复制业务逻辑。

提交从复核到下单/回滚不含阻塞调用。最后一次经济写入后释放本事务锁，在commit返回前重置成功计数、退避及搜索状态，并写下最终RESULT和船只日志。异常终止仅释放本事务持有的锁；Debug可标记aborted，已提交队列和航次身份保留。价格波动允许重新定价，但必须再次通过资金及NPC正价差规则。

空闲返航使用优先级1的专用poll，以30游戏秒信号检查，遇袭响应优先；无任务时保留移动调用栈。已有贸易队列不会为新版重新分配；无任何订单的余货仍沿用虚拟清仓（删除并按商品均价补偿玩家）的继承行为。

## 保留的继承修复

### 其他骡子与继承修复

M1、M2、M3 仍保留在本基线中。它们没有被 M4 替换或删除；以下是本次基线包含的前期修复，不应误读为三种行为完全重写。

| 行为/文件 | 改动 | 原因 |
|---|---|---|
| M1 旅行骡子 / `travel_mule.xml` | 自定义目标列表下，距离 15 也表示不限跳数；较小值仍限制，黑名单继续生效 | 统一手动目标与自动搜索的距离约定 |
| M2 空间站骡子 / `station_mule.xml` | 中间产品判断改为实物库存/分配量，库存超过 30% 才应用原跳过规则 | 原判断混淆了买报价需求比例与现有库存比例 |
| M2 空间站骡子 | 修正“仅非法商品”的 ID 比较 | 正确保留原来列出的四种商品，不把错误表达式当作筛选条件 |
| M2 中文说明 | “强制卖出”改为“将目标设为贸易仓库”，解释会添加商品和买卖报价 | 提醒玩家该功能会改变目标站的贸易商品设置，关闭开关不会自动撤销已创建项目 |
| M3 分配骡子 / `distrib_mule.xml` | 保留既有分配逻辑，澄清仓储门槛说明 | 没有把其起运门槛设计误当成确认错误 |
| 旧报价评估助手 | 小额补齐例外扩展到普通买单；评分用实际数量；建造仓同分换单同步更新需求、货源和数量 | 修复小单饥饿、收益被整船容量夸大和报价配对不一致；新 M4 的主要流程已改走船队调度器 |
| 旧 M4 兼容路径 | 非空抽样列表至少留一条；修正星区服务层次；模仿补传原有搜索参数 | 避免继承路径继续保留已确认的错误；旧参数不再控制新调度器的候选截断 |

## 验证边界

本地XML解释器验证分支与数量，XSD验证结构，安装测试验证归档。它们不证明原生调度、保存序列化、飞行、泊位等待或SETA下FPS。验收以[测试指南](TESTING.zh-CN.md)中的存档11后续复测为准。
