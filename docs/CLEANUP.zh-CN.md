# 代码清理说明（2026-10-23）

本次扫描覆盖全部运行时AI脚本、MD事件脚本、原版差分补丁、图标和语言资源，检查脚本调用关系、不可达代码、废弃参数转发及安装归档。不是只按文件名判断是否删除。

## 已删除

| 位置 | 删除内容与原因 |
|---|---|
| `aiscripts/supply_mule.xml` | 424行旧采购循环及其专用准备逻辑。新版共享调度调用后的无条件返回使旧循环不可执行 |
| `aiscripts/mule.lib.evaluate_tradeoffers.xml` | 253行旧报价评估。唯一调用者是已删除的旧M4循环 |
| `aiscripts/quicksort.xml` | 115行旧排序。仅被旧报价评估调用，新容量排序不使用它 |
| M4下属复制、模仿及名单重建 | 停止向新调用转发已退役的购买比例、搜索强度等字段。内部订单参数定义仍保留用于加载旧存档 |
| 旧算法测试 | 删除只检查已删除实现的测试；保留其他骡子回归，并增加返航、配置快照和名单重建测试 |

三个主要位置共删除792行旧逻辑与旧辅助代码。它们原本主要是不执行或无调用的代码，清理改善维护性，不应据此宣称游戏帧率明显提高。

## 检查后保留

| 内容 | 保留原因 |
|---|---|
| `station_mule`、`travel_mule`、`distrib_mule` | 仍是可选的游戏行为入口，无普通脚本调用不代表没有使用 |
| `mule.lib.empty_cargo` | 上述三个行为仍会调用 |
| `mule.lib.debug.dump_tradeoffers` | 旅行骡子仍用于报价诊断 |
| `order.assist` 与 `lib.request.orders` 差分 | 支持模仿行为，并防止原版站属派单覆盖骡子行为 |
| 历史参数定义、版本补丁与旧语言ID | 服务旧订单和存档加载；不因界面隐藏就直接删除 |
| 旅行骡子末尾不可执行的14个等待占位 | 原作者明确用于保持旧存档的阻塞动作索引。没有运行成本，直接删除可能影响加载 |
| 空间站骡子的条件式 `continue` | 带有 `chance` 条件，后面的代码仍可执行，不属于死代码 |
| MD设置、事件监听、更新提示及图标/翻译资源 | 有引擎事件、订单界面或文本引用用途 |

## 核对结果与边界

清理后有27个运行时XML源文件、18个完整AI脚本；安装包额外生成英文l044资源，CAT/DAT共28项。所有固定名称脚本调用均能在模组或原版中找到；模仿补丁的动态调用对应四种已注册骡子行为。

116项脚本回归、2项安装包测试、24项原版XSD验证及3处原版补丁选择器检查通过。检查使用真实XML和本地合成适配器，不代替原版引擎中的移动、存档序列化和性能测试。

本地安装同时从CAT/DAT移除两个废弃脚本，避免只删源码却留下旧归档内容。旧安装包备份保存在游戏的 `support` 目录中，不参与加载，不改动玩家存档。清理结果纳入 `v0.1.0-beta.1`，发布方式见[版本指南](VERSIONING.zh-CN.md)。
