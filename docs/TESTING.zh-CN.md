# 基线测试指南

测试使用存档副本，完整退出并重启 X4 后进行。当前对照游戏结构为 X4 8.00；其他游戏版本或覆盖相同脚本的模组需要另测。

## 已完成和未完成的验证

| 层次 | 状态 | 能证明什么 |
|---|---|---|
| XML 控制流/算术/边界测试 | 105 项通过，可用 `python tests/checks.py` 重现 | 实际 XML 在合成引擎适配器上的分支、数量和编排行为；包含本次玩家优先级回归 |
| 原版 XSD | 26 个 AI/MD/差分 XML 通过 | 动作、参数与 XML 结构符合当前提取的游戏模式 |
| 原版补丁选择器 | 3 处各匹配一次 | 当前版本中所覆盖的原版节点可以定位 |
| 既有游戏测试反馈 | 容量排序、多笔贸易、微量需求分单、小船忙后扩大派遣、取消后重派 | 玩家已有实验中观察到对应行为；不是最新全部代码的连续回放 |
| 优惠价格查询、返航与逐船界面 | 继续待测 | 本地适配器不等同原生价格过滤、事件、移动和 UI |
| 200 艘 S；5 XL + 10 L + 20 M 等规模 | 没有实际 FPS 数据 | 不能承诺规模增大后无卡顿 |

适配器不模拟真实飞行、原生预订显示时序、游戏保存序列化、泊位排队或其他模组的事件覆盖。

## 采购与容量

| 编号 | 准备及操作 | 预期 |
|---|---|---|
| C01 | 新建 M4，查看参数 | 默认最多 3 笔、75% 装载、走廊 2 跳、每跳 5%、自有库存门槛 50% |
| C02 | 沿用曾被上游设为 1 笔的船 | 旧值保留；手动改为 3 后按三笔上限组合 |
| C03 | 10 种货各缺 1，10 艘小船，最多 3 笔，其他条件相同 | 多船分担需求，每船不超过 3 笔；不因装载率而永久剩下尾单 |
| C04 | 同时存在 90K L 船与 30K XL 船、大额需求 | 实际 90K 先于 30K，不能仅因 XL 等级压过 L |
| C05 | 一艘 5K、多艘 30K 和 90K；组合均不足 75% | 正常阶段失败后，从 5K 向 30K、90K 豁免；小船忙时其他船继续接剩余需求 |
| C06 | 同型号增加/移除一艘，再加入新容量型号 | 数量和成员更新正确；新型号进入对应容量位置 |
| C07 | 给不同型号/改装船设置同一显示名称 | 不仅凭显示名称分组，运输类型和实际容量仍生效 |
| C08 | 最近厂产品 A 不够，允许路径范围内另一厂也卖 A | 可分成两笔采购凑货，笔数分别计入上限 |
| C09 | 多笔采购后送同一站 | 队列先采购，后交付；不超共享仓容和累计资金 |
| C10 | 多艘船同时面对同一个小买单/小供应量 | 预订不会双重扣减，也不超量反复派单 |
| C11 | 手动取消一艘船的未完成贸易 | 清理失效占额，其他空闲船能在后续轮次接手 |
| C12 | 军舰参与，运输仓型和停靠条件都成立 | 不因军舰类别直接排除；无人机条件仍须满足 |

## 货源、路径与价格

| 编号 | 准备及操作 | 预期 |
|---|---|---|
| P01 | 同一货源优先级内，近处合法货源较贵，远处较便宜，均满足主单条件 | 主单优先近处；同跳数才比较实际价格 |
| P02 | 同跳数，原价更贵的厂享优惠后更便宜 | 使用优惠后实际估价选货源；提交前优惠变化则拒绝旧草案并重排 |
| P03 | 路径内 B=103，一跳外 B=100，加成5% | 选择路径内103，另一来源竞争估价105 |
| P04 | 只有一跳外的合法 B=100 | 不因加成105高于另一虚构报价而拒绝；真实外购价差仍需成立 |
| P05 | 将加成设0，副单范围仍设1 | 不惩罚价格，但不能去偏离2跳的星区 |
| P06 | 供应站在副单范围内，却超出基点总范围 | 拒绝，不能利用副单逐站扩张突破基点上限 |
| P07 | 中途改变旅行/活动黑名单或贸易规则 | 下一次原生报价/路径查询按实际船和民用规则检查；在途原版订单的重规划另外观察 |
| P08 | 自有某商品分配10000，门槛60%，库存6000、6001 | 前者不参与，后者可参与 |
| P09 | 同站库存8000、需求7000、门槛60% | 合法报价允许时可搬7000，不强制留下6000 |
| P10 | 自有站零分配量；门槛0/100 | 零分配量跳过；0仍需正库存；100需要严格超出分配量 |
| P11 | 玩家供应厂2跳、NPC厂1跳，均合法且有同商品；切换“优先从玩家进货” | 开启先选玩家厂，关闭先选更近NPC；关闭优先不禁止自有供货 |
| P12 | 纯贸易库存有手动买报价，无生产模块 | 无“允许商品”开关也可采购；只生产不消耗的最终产品过滤单独检查 |
| P13 | 基点为星区，只服务基点，星区有6玩家站及NPC站 | 给玩家站补货；NPC可作合法货源，不自动作为这类送货对象 |
| P14 | 两种优先模式分别测试玩家库存低于/等于门槛、零分配量 | 均不使用该自有货源，可在允许时回退NPC |
| P15 | 自有厂提供30件、NPC提供100件，需求100件、最多3笔，开启优先 | 先取自有30件，再从NPC补70件；不超需求或最大笔数 |
| P16 | 同种副单有合格玩家及NPC货源；再把玩家货源移至走廊范围外 | 开启时优先范围内玩家；关闭按普通估价比较；越界玩家不能因优先而入选 |
| P17 | 关闭优先并关闭NPC货源，仅保留库存过门槛的自有厂 | 自有厂仍可供货；NPC开关只控制真正NPC |
| P18 | 派单草案计算期间切换优先开关或库存门槛 | 提交复核拒绝旧配置，下轮重排；已提交订单不主动取消 |

## 空闲、诊断与货物

| 编号 | 准备及操作 | 预期 |
|---|---|---|
| I01 | 所有成员空闲且远离站基点 | 返回基点站所在区域附近，不要求停靠、不占贸易泊位 |
| I02 | 基点为星区 | 进入该星区即可待命，已经在其中不反复飞行 |
| I03 | 一艘仍有贸易，其他船空闲 | 不启动新的整队返航；全部空闲后触发 |
| I04 | 回程中产生可执行需求 | 每段最长30秒后回到调度；加上调度退避/队列切换延迟后可在抵达前接单 |
| I05 | 回程中手动命令、换行为/基点、解除绑定或玩家驾驶 | 不覆盖手动队列，不强制拉回旧基点；观察原版中断和下一次资格检查 |
| I06 | 禁止回基点的唯一路径 | 不强闯；本船失败提示显示返航路径受阻，仍保留后续搜索 |
| I07 | 两艘同型号大船及交易对象均无货运无人机 | 每艘自己的行为提示说明缺少货运无人机，不串写其他船名/编号 |
| I08 | 给船或交易站补货运无人机，随后成功接单 | 清除该船旧失败提示；其他贸易条件仍须成立 |
| I09 | 价格倒挂、库存门槛不足、无泊位、资金不足分别复现 | 原因与具体数值对应；最后原因不宣称是所有候选的唯一原因 |
| I10 | 消除全部需求 | 正常等待、清除旧采购失败；在基点区域不反复返航 |
| I11 | 一艘无订单船手动装余货；另一艘保留正常交付队列 | 前者虚拟清仓并按实际删除量×商品均价补偿个人账户；后者货物保留 |
| I12 | 回程/多单在途中保存，退出重启再读取 | 不重复预订、不永久卡在返航、仍能继续调度 |
| I13 | 模仿船，指挥官设置60%或0%门槛并切换优先开关 | 继承开关与准确门槛，0不得变为50%；保存重载后继续观察 |

## 性能实验建议

在相同存档、镜头、游戏速度和活动范围下，分别测试单船、200艘S、混合大中小船。记录空闲、首次建立索引、持续大批需求、无货源、优惠报价密集等场景的平均帧率和明显卡顿持续时间。开启磁盘日志与关闭启动参数各测一次，区分日志写入开销。

这是一组待执行实验，不是当前性能承诺。请同时记录游戏版本、CPU、模组列表、范围内站数/货物数及是否使用 SETA。
