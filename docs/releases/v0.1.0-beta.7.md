# v0.1.0-beta.7 · 柔性货量分级与返航重搜

内部版本669；日期2026-10-25；扩展ID保持`ws_2013772865`。本地压力测试包，尚未发布到GitHub。

本版针对大小船争夺主单、返航后很久才重新搜单，以及提交时余量减少导致整趟草案作废，调整订单分配。实际运输时间、NPC生产/价格演变及意外事件的模拟环境留待游戏压力测试之后再建立。

## 分级分配

- 按同基点、兼容商品的空闲成员实际货仓体积排序；一档最大/最小仓容不超过1.5倍，以档内最大仓容作参考，不按M/L/XL标签分档。
- 在本船已通过资格检查的候选池中，用净需求和净可售量估计可运体积，避免仅凭空间站需求将缺货的大单认作大宗运输。该体积是上界，路线、资金等最终可执行性仍由本船检查。
- 主单优先匹配容量档。对同收货对象、同仓型最多允许笔数的组合估计，去重货源并累计扣减同一买单需求；几笔中等订单也可提供给大船。零散小单仍优先小船。
- 副单不受档位限制。分级没有经济占额，不阻塞其他船搜索；等待90游戏秒、3轮未获任务或进入装载豁免时，允许跨档主单。已忙碌的大船不参与占据档位。
- 不保证严格轮流派单、全局最优组合或每艘船始终有任务；同档船仍独立竞争，跨档补舱仍可能消耗大宗货源。

## 返航、等待与提交

返航信号启动专用`poll`脚本，中断优先级1高于普通移动的0、低于原生遇袭响应的10；无任务时保留移动调用栈。每30游戏秒再次发信号，过期返航序号不启动搜索。解决旧轮询目标脚本默认0优先级不能启动全局中断的问题。受到高优先级响应或计算耗时影响时，实际搜索开始时间可以晚于30秒，需看`RETURN_POLL → RETURN_SEARCH → BEGIN`核对。

装载门槛按未获任务的游戏时间调整：未满2分钟沿用设置；2分钟后不高于50%；5分钟后不高于25%；10分钟后豁免装载率。连续三次完整装载不足仍使下一轮提前豁免。返航、退避及额度耗尽不重置等待起点；成功派单或更换配置后重置。资金、价差、权限、黑名单、范围、走廊、泊位、无人机及交易最小量等条件始终保留。

发现净供需缩水时，只修复一次：按最新数量重建原有采购，再从同轮候选补最多2笔，额外检查最多12个候选；不重新扫描全宇宙。修复须满足本轮有效装载率，随后再次验证报价、价格、资金、仓容、净数量与船只身份，最后在短锁内下单。修复不足或余量再次变化时拒绝提交，保留具体失败说明。成功记录反映修复后的实际数量。

## 共享粗筛与日志

同基点/商品共享大货量、近距离、低原始报价的排序，30游戏秒过期，新报价、索引重建和加载使相关缓存失效。共享排序不含个人黑名单、停靠资格、资金或优惠，不能把某艘船的失败共享给其他船。原生报价索引仍按已知报价发现机制更新，不是逐帧读取全部NPC工厂实物库存。

普通船只日志补充候选需求/供货上界、分级等待、有效装载率、同收货对象/仓型与笔数限制。Debug保留`player.age`游戏时间、船号和attempt；新增`RETURN_POLL`、`RETURN_SEARCH`、`LIMITS`、`REPAIR`，最终`RESULT`同时记录实际体积、等待、门槛、修复及计算计数。需求/供货上界仅代表本轮候选池，不应当作全宇宙无货的证明。

## 验证与安装

本地实际XML回归、安装包检查、原版XSD、动作库引用及原生补丁选择器结果见[测试指南](../TESTING.zh-CN.md)。这些检查不能证明原生飞行、SETA重搜间隔、实际CPU/FPS或长期利用率。

安装包：`Mules-Supply-Mod-OPUS-v0.1.0-beta.7.zip`。完整退出并重启X4后加载测试存档，Debug中的新`BEGIN`应含`build=beta.7`；已有贸易订单继续执行。

待玩家执行：开启SETA运行30现实分钟、关闭SETA运行1现实小时；分别保存起点与终点并保留Debug。用存档游戏时间界定每段窗口，不要求保存与Debug开关完全同步。两段窗口中的生产、报价、异常和实际运输耗时分析在测试后进行。
