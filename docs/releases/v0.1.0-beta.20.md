# v0.1.0-beta.20：M4日志口径与原生验收

内部682，日志schema=9，贸易策略标记beta.19。本版已通过本地检查及2026-10-28普通速度/SETA原生日志验收，以beta测试版发布。

修复前，搜索得到的装载率可能与提交前修复后的体积混在同一条RESULT中。例如搜索80/100，提交前缩为60/100时，旧记录可能把80%与60m³并列。现在分别记录searchLoadPercent=80.00、committedLoadPercent=60.00及各自体积、容量和状态。失败时提交字段为null/not_committed；orders_created只表示订单创建成功，不表示已经装货或交货。BEST、END、DRAFT_LEG明确stage=search；REPAIR记录修复前数据及尝试结果，不冒充最终提交。

容量分母沿用现有算法的最后一笔货物整件最大容积，记录capacityBasis=last_ware_whole_unit_limit；混合货物的整件舍入可能使比率略高于100%，保留原值供分析，不据此推断实际超载。游戏日志簿也使用固定两位小数，明确是方案而非实载，并修正失败说明与余货回收的Cr文本精度。实际金额和付款逻辑不变；机器核对继续使用整数ct。

所有M4字面事件构造器补上独立事件名和字段清单，格式化失败会报告原事件、输入和可用原始ct。未查询数据、未记录历史、未观察到终局、引擎未提供原因分别说明，避免笼统unknown。无法单独归因的表达式列出涉及字段，不伪称已识别某一个底层字段。COUNTS_SUMMARY明确只覆盖规划枚举明细及汇总前的格式失败，不代表整个航次或磁盘写入完整。重复终止回调保留原生通知，但只输出一次订单结局；ORDER_OBSERVED使用订单自己的历史标记。

保留单一Debug开关和四路文件。相对冻结beta.19，剔除Debug块及纯显示输出后的28份非展示AI动作树一致；M1–M3、M4入口和模仿分支字节一致。没有修改贸易条件、派单数量、分级、等待降级、192/128限额、路线和评分。不能由此保证所有游戏场景无缺陷。

本地验证：259项适配器测试（含60项日志观察），2项包体测试，37份XML原生XSD、3个原生补丁选择器、22个动作库/180处引用。14种市场情形、Debug开/关各一组，共28组beta.19→beta.20经济效果比较一致；覆盖正常、混合船队、价差、资金、黑名单、自有货源、无需求、小单、建单失败、部分建单、提交修复、装载失败、延迟预订和搜索限额。额外核对Debug开关前后效果一致。适配器不模拟原生MD事件调度。

自上一公开beta.9以来还包含：等待输入及原生键契约修复、可靠SESSION与金额探针、整数ct/Cr精度、订单及候选完整性标记；移除玩家货源优先和玩家库存门槛，改用原生可售报价；百万倍率运量评分；移除“从AI派系中收集”选项并忽略其旧关闭值。各版本细节见beta.10–19历史说明。beta.18的存档4→2长测验证了704条QUEUE与ORDER_CREATED成对及351条BEST评分，不是beta.20的原生验收。

安装前正常退出X4，备份实装和存档。使用ZIP中的mules_supply_mod_opus文件夹；不要同时启用原版骡子。新建测试基点，不覆盖已有证据。复现本轮测试可按[M4指南](../M4_DEBUG.zh-CN.md)建立新基点，先普通速度再SETA。大船在搜索限额下可能多轮等待后放宽门槛接小单，仍是现有策略；本次不改变。
