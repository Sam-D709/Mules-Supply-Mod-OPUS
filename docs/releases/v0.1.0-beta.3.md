# v0.1.0-beta.3 — M4 logging update / M4 日志优化

Public pre-release · 2026-10-23 · X4 internal version 665

## English

### Changes since the public beta.1

- One compact ship-log entry per actual dispatch: settings, normal or relaxed tail mode, selected purchases, prices, total cargo load and why combination stopped.
- Idle and failed-commit summaries have a 10-minute cooldown, checked before formatting. Price/stock fluctuations do not bypass it; successful dispatches are still recorded each time.
- Rejections are aggregated using existing checks: price failures and the smallest actual price gap, corridor failures and the smallest excess jump count, plus route/other filters. Counts are first-failure observations, not unique supplier counts or proof that all remaining checks pass. No extra source, route or price queries are added for these summaries.
- Optional **Debug: detailed disk logging**, off by default. Detailed candidates go to disk instead of flooding ship logs. With Debug off, verbose formatting and calls are skipped. Routine M4 file diagnostics use the same switch.
- Existing queued trades and historical logs are preserved; only obsolete full-report caches from the unpublished local beta.2 build are removed. Procurement rules remain those of beta.1.

### Dependencies

Core procurement and compact logs have **no mandatory third-party mod dependency** and no declared additional DLC requirement.

| Mod | Status |
|---|---|
| [SirNukes Mod Support APIs](https://steamcommunity.com/sharedfiles/filedetails/?id=2042901274) | **Optional; required only for the Extension Options Debug menu.** Without it, that menu is unavailable; core procurement does not depend on it. |
| kuertee UI Extensions and HUD | Not required; no direct UIX API dependency. |
| Civilian Fleets | Optional compatibility detection to avoid duplicate subordinate behavior synchronization. |
| Subordinate Order Access | Optional order-management convenience. |

SWI, ship_sorter, TacticalResponsePolice and Options Helper are not requirements. The original Mules mod is included/replaced: **do not enable both versions**.

For detailed disk logs, launch X4 with **`-scriptlogfiles`**, then enable **Extension Options → Mules-Supply-Mod-OPUS → Debug: detailed disk logging**. Output: `Documents/Egosoft/X4/[user ID]/logs/MulesExtended/debug.txt`. Native scripts cannot write directly into the mod installation folder. The toggle is saved per savegame. Turn it off after reproducing a problem; detailed disk output can still be expensive.

### Install and upgrade

Download [Mules-Supply-Mod-OPUS-v0.1.0-beta.3.zip](https://github.com/Sam-D709/Mules-Supply-Mod-OPUS/releases/download/v0.1.0-beta.3/Mules-Supply-Mod-OPUS-v0.1.0-beta.3.zip) and optionally verify it with [SHA256SUMS.txt](https://github.com/Sam-D709/Mules-Supply-Mod-OPUS/releases/download/v0.1.0-beta.3/SHA256SUMS.txt). Use the named ZIP under Assets rather than Source code.

Exit X4, back up your saves, and move the previous mod folder outside `extensions`. Extract the ZIP and drag its single **`mules_and_warehouses_extended`** folder into `X4 Foundations/extensions`. No compilation is required. Old log entries remain; an already bloated logbook may still be slow to open.

### Validation and next stage

**127 script checks, 2 package checks, 28 XML structure checks and 3 native patch selectors passed.** Package extraction, CAT/DAT contents, bilingual resources and Debug ON/OFF decision parity were checked locally. Existing gameplay feedback is from X4 8.00 Hotfix 4 (legacy) + SWI. Native menu display, file output, operation without the optional API, and actual FPS improvements still need gameplay verification. No measured FPS gain is claimed.

**Unresolved:** a draft does not retry with a different main ware or main supplier when its first executable main source produces an underfilled combination. A nearby low-stock factory can repeatedly anchor the draft after producing small quantities. The next stage will evaluate bounded alternative-main/source retries and a per-round calculation budget. Empty offers and fully reserved stock are already skipped. This release changes logging only and does not fix this selection limitation.

## 简体中文

### 相比公开 beta.1 的变更

- 每次实际派单只写一条船只摘要：现有配置、正常/尾单解限模式、采购组合、实际价格、总装载率及停止组合的原因。
- 待命和提交失败简报先检查10分钟冷却，再生成文本；价格和库存波动不绕过冷却。每次成功派单仍会记录。
- 复用已有计算，汇总价格失败次数、最小实际价差缺口、偏离范围失败次数与最小超出跳数，以及路径和其他过滤。次数是首次失败条件的检查次数，不是去重后的工厂数量，也不保证其余条件通过；不增加货源、路径或价格查询。
- 新增默认关闭的 **Debug：详细磁盘日志**。候选详情只写磁盘，不再向船只日志逐条分页；关闭时跳过详细文本生成与调用，常规M4磁盘诊断也统一受此开关控制。
- 保留现有排队订单和历史日志，仅清理未公开的本地beta.2版废弃报告缓存。采购规则沿用beta.1。

### 依赖与可选模组

核心采购、简要日志**没有第三方模组强依赖**，未声明额外DLC要求。

| 模组 | 作用 |
|---|---|
| [SirNukes Mod Support APIs](https://steamcommunity.com/sharedfiles/filedetails/?id=2042901274) | **可选；使用扩展选项中的Debug菜单时需要。** 不安装则无此菜单，不影响核心采购。 |
| kuertee UI Extensions and HUD | 不需要，本版没有直接调用其接口。 |
| Civilian Fleets | 可选兼容检测，避免重复同步下属行为。 |
| Subordinate Order Access | 可选的下属命令管理便利工具。 |

SWI只是测试环境；ship_sorter、TacticalResponsePolice 和 Options Helper 均不是依赖。原版骡子已包含/替换，**不要同时启用两版**。

详细日志需以 **`-scriptlogfiles`** 启动游戏，再开启 **扩展选项 → Mules-Supply-Mod-OPUS → Debug：详细磁盘日志**。文件位于 `Documents/Egosoft/X4/[用户ID]/logs/MulesExtended/debug.txt`，原生脚本不能直接写入模组安装文件夹。开关随当前存档保存；复现后关闭，详细磁盘输出本身仍有开销。

### 安装与验证

下载上方命名的安装ZIP及校验文件。完整退出游戏、备份存档，将旧模组文件夹移至 `extensions` 以外，解压后把唯一的 **`mules_and_warehouses_extended`** 文件夹拖入游戏 `extensions`，无需编译。历史日志不清除，已经膨胀的日志页仍可能打开较慢。

**127项脚本、2项安装包、28项XML结构及3处原版补丁选择器检查通过。** 已核对实际解压、CAT/DAT、中英文资源及Debug开关不改变采购决策。现有游戏反馈来自X4 8.00 Hotfix 4 (legacy) + SWI。菜单显示、真实文件落盘、未安装可选API时的运行以及FPS变化仍需游戏实测，本版不宣称已有FPS测量结果。

### 下一阶段：主单选择与低库存货源

**尚未修复：** 当前第一笔合法主单组合后装载不足时，不会换主商品或另一主单货源重试整趟草案。近处工厂少量补产后可能反复成为主单，其他商品本来可能组成更适合大船的订单。下一阶段拟评估有次数上限的主商品/货源重试，并控制每轮计算预算。空报价和已被预订完的库存本来就会跳过，本版仅更改日志。
