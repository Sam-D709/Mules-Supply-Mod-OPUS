# Mules-Supply-Mod-OPUS

**简体中文** | [English](README.en.md)

**公开测试版：[v0.1.0-beta.3](https://github.com/Sam-D709/Mules-Supply-Mod-OPUS/releases/tag/v0.1.0-beta.3) / 内部665。** [本次发布说明](docs/releases/v0.1.0-beta.3.md) · [日志与Debug指南](docs/SHIP_LOG.zh-CN.md)：船只日志只记实际派单与冷却简报；扩展选项可开启详细磁盘日志，默认关闭。采购规则沿用beta.1。

面向 **X4: Foundations** 的供应优化模组，基于 **Mules, Supply and Warehouses Extended 6.60**，主要重写 **M4 采购骡子**：按真实货仓容量分配任务，多笔采购合并运输，小额缺货也能补齐。M1、M2、M3 保留。
目前仅在X4 Version 8.00 Hotfix 4 (legacy) + SWI星球大战模组中进行测试，至于原版 8.0 与 9.0 并未做测试，如果有任何适配性问题欢迎提出Issue

## M4 参数对照

以下“原版”指骡子模组 6.60。参数名称采用其中文界面名称；新版数值为新建行为的默认值，已有船的设置可能保留。

| 原版参数 | 新版参数与设置 | 为什么修改 |
|---|---|---|
| 最大交易次数：固定 1 笔 | 同名；**默认 3 笔，可设 1～10 笔** | 当工厂A的供应并不能装满货船，货船可选择顺路去其他工厂购买其他需求货物，设定基点空间站A到工厂A所经过的星区为主要路径，飞船会在这些主路径星区范围3跳内（参数可设置）其他星区寻找次要订单，只要这几笔订单（最多为最大交易次数值）总和大于设定的飞船仓储，即可提交订单 |
| 货仓装载 %：25～95%，默认 75% | 同名；**0～95%，默认 75%**，判断整趟采购的合计装载率 | 主要订单和所有次要订单占货仓合大于此值，即可进行交易 |
| 从玩家收集 | **优先从玩家进货**；默认开启 | 开启时，主单和副单优先选择库存超过门槛的合格玩家货源，不足时再由NPC补足；关闭时，合格玩家货源与NPC按相同的距离和估价规则竞争，不会禁止自有供货。 |
| 玩家购买模式：自有卖价的判断倍率，0～100%，默认 100% | 删除，改为 **玩家工厂存货超过%时允许供货**；0～100%，默认 50% | 两种优先级模式下均需严格超过门槛；等于或低于门槛不参与供货。此值是参与门槛，不是运输后的保留库存。 |
| 评估的交易 %：5～100%，默认 100% | **删除可见参数**，由调度器完整检查候选并分批计算 | 此参数原本决定搜索订单的频率，但我认为其对于性能的影响非常小，没有必要展现 |
| 允许建材 | **为建造仓采购材料**；默认开启 | 变更中文翻译，其可以为建材仓库贸易 |
| 允许原材料 | **采购本站不生产的消耗物资**；默认开启 | 即该工厂原材料不足时对原材料进行贸易 |
| 允许中间产物 | **采购本站自产自用的物资**；默认开启 | 即该工厂中间产物不足时对中间产物进行贸易 |
| 允许商品 | **删除可见开关**，纯贸易库存按合法买报价补货 | 个人认为该参数没有任何存在的必要，因为启用仓库贸易本身就会放出收购表，飞船完全可以根据该收购表进货 |
| 仅服务基点空间站/星区 | **仅给基点空间站/星区补货**；默认关闭 | 基点选择为某空间站时：关闭该参数，为该星区其他玩家空间站贸易，开启时只为该空间站贸易，，，基点选择为某星区时：关闭该参数为其他邻接星区玩家的空间站进行贸易，开启时只为该星区玩家所有空间站进行贸易 |
| 无 | **副单离主路径范围（跳）**；0～10 跳，默认 2 跳 | 距离主要订单路径星区多少范围的星区内寻找次要订单 |
| 无 | **副单偏离每跳估价加成 %**；0～50%，默认 5% | 次要订单所在星区距离主路径越远，虚拟价格越高，每跳增加5%价格，该虚拟价格生效仅发生在以下情况：邻接星区有多个符合的同种商品，采用这种价格表示路程成本，如果只有一种次要订单该虚拟价格失效 |
| 基点 空间站/星区、分配到空间站下属、最大活动范围 | **保留** | 是否分配到具体空间站下属作为贸易商？ |
| 从 AI 派系中收集、锁定自定义商品列表、商品（默认全部） | **保留** | 是否从NPC工厂进货？ |

## 详细算法介绍

M4 以同一基点的船队为单位，按照**实际货仓容量从大到小**分配任务。无法达到装载率的剩余需求，再按照**容量从小到大**逐级解除装载率限制，避免小额缺货长期无人处理。

以下示例统一使用这些条件：

| 项目 | 设置 |
|---|---|
| 型号 A | 货仓容量 16,000 m³，共 2 艘 |
| 型号 B | 货仓容量 5,000 m³，共 5 艘 |
| 货仓装载比例 | 90% |
| 每趟最大采购笔数 | 3 笔 |
| 副单离主路径范围 | 3 跳，示例中手动设置 |
| 商品体积 | 每件均为 1 m³ |

正常派单时，A 型船至少需要组合 **14,400 m³**，B 型船至少需要组合 **4,500 m³**。

示例默认货源充足、价格合法、船只能够停靠，并满足资金、无人机和黑名单等条件。实际游戏中的不同商品体积可能不同。

### 一、单种货物：大船让位，小船补齐

空间站需求：**9,000 件能量电池**。

1. **A 型船评估订单。**  
   装载率为 `9,000 ÷ 16,000 = 56.25%`，未达到 90%，也没有副单可以补充，因此交给更小容量的船评估。

2. **第一艘 B 型船接单。**  
   可以运输 5,000 件，达到满载，接下这部分需求。

3. **剩余需求为 4,000 件。**  
   对另一艘 B 型船来说，装载率为 `4,000 ÷ 5,000 = 80%`，正常阶段无法接单。

4. **进入尾单阶段。**  
   B 是当前最小容量型号，空闲 B 型船解除装载率限制，接下剩余 4,000 件。

**最终结果：两艘 B 型船分别运输 5,000 件和 4,000 件，A 型船保留运力。**

### 二、多种货物：沿主路径组合采购

空间站需求：**9,000 件能量电池、6,000 件 BoFu**。

1. A 型船仅运输能量电池时，装载率不足，因此继续搜索副单。
2. 以“基点 → 能量电池供应站”的路径为主路径，在允许偏离的 3 跳范围内寻找 BoFu 货源。
3. 如果找到合法货源，两笔采购的合计体积为：

   ```text
   9,000 + 6,000 = 15,000 m³
   15,000 ÷ 16,000 = 93.75%
   ```

4. 达到 90% 装载率，A 型船执行两笔采购，然后返回收货站交付。

```text
基点空间站 → 能量电池厂 → BoFu 供应站 → 收货空间站
```

> 如果 BoFu 需求只有 5,000 件，两单合计为 14,000 m³，装载率只有 **87.5%**，仍不能让 A 型船在正常阶段出发。它需要继续寻找第三笔采购，或者让剩余需求进入后续派单阶段。

### 三、零散缺货：限制采购笔数，让多艘船分担

空间站各缺 **1 件医疗物资、能量电池、BoFu 和先进电子设备**。

- A 型船最多组合 3 笔，总体积仍远低于装载率要求，正常阶段不接单。
- B 型船同样无法达到装载率要求。
- 尾单阶段优先让空闲 B 型船解除装载率限制，接下其中 3 笔。
- 剩余 1 笔由另一艘空闲 B 型船接手。

如果 B 型船全部忙碌，尾单可以继续分配给空闲 A 型船，A 型船同样解除装载率限制。如果所有船都忙碌，则等待运力释放。

**最大采购笔数仍然有效。** 即使一艘船装得下全部货物，也不会超过每趟设定的采购笔数。

### 四、单个工厂供货不足：同一种商品也可以拆成多笔

空间站需求：

| 商品 | 需求 |
|---|---:|
| 能量电池 | 9,000 件 |
| BoFu | 5,500 件 |

附近一个能量电池厂只能提供 6,000 件，另一个合法供应站可以提供剩余 3,000 件。

在路径、报价等条件允许时，一艘 A 型船可以组合：

| 采购笔数 | 内容 |
|---|---|
| 第 1 笔 | 从供应站甲采购 6,000 件能量电池 |
| 第 2 笔 | 从供应站乙采购 5,500 件 BoFu |
| 第 3 笔 | 从供应站丙采购 3,000 件能量电池 |

```text
合计体积：6,000 + 5,500 + 3,000 = 14,500 m³
装载率：14,500 ÷ 16,000 = 90.625%
```

达到装载要求，可以出发。**同一种商品来自不同供应站，会占用不同采购笔数。**

### 五、小船全部忙碌：大船也能处理尾单

假设正常派单结束后，空间站仍缺 **2,000 件能量电池**，所有 B 型船都在执行任务，但还有 A 型船空闲。

尾单阶段先检查小容量船，发现没有空闲 B 型船后，继续向上检查 A 型船。空闲 A 型船解除装载率限制，接下这笔需求，无需一直等待 B 型船返航。

```text
优先使用空闲小船
        ↓
仍有需求，继续使用空闲大船
        ↓
所有船都忙碌，等待运力释放
```

解除的只有**最低装载率限制**。缺少货运无人机、无法停靠、路径被黑名单禁止、资金不足等问题，不会因为进入尾单阶段而被忽略。

### 六、货源选择：先判断玩家优先级，再比较距离或绕路

开启“优先从玩家进货”时，对当前要采购的商品，先选择库存过门槛且能执行贸易的玩家货源；没有合格自有货源或其数量不足时，再用NPC货源补足。主单和副单都应用此优先级，但不会改变需求本身的大小及用途排序。

同一货源优先级内，主单先比较距基点的**合法星区跳数**，同跳数再比较实际采购价格，包括能够取得的优惠。关闭“优先从玩家进货”后，不再区分货源优先级，合格玩家货源和NPC一起按此规则竞争。

例如，玩家供应厂距离2跳，NPC工厂距离1跳，两者都能满足同一商品需求：开启优先选玩家供应厂；关闭优先选更近的NPC工厂。

主单确定后，固定“基点 → 主单货源”的路径。副单供应站必须同时满足：

- 位于基点最大活动范围内；
- 距离主路径不超过设定的副单偏离范围。

同一种副单商品在同一货源优先级内有多个货源时，按以下估价竞争：

```text
竞争估价 = 实际单价 ×（1 + 偏离跳数 × 每跳加成百分比）
```

假设每跳加成为 5%：

| 货源位置 | 实际单价 | 偏离主路径 | 竞争估价 |
|---|---:|---:|---:|
| 主路径内 | 103 | 0 跳 | 103 |
| 主路径外 | 100 | 1 跳 | 105 |

此时优先选择主路径内报价 103 的货源，以减少绕路。

**竞争估价不会改变实际付款。** 如果只有偏离一跳的那个合法货源，它仍然可以入选，实际采购单价仍为 100。每跳加成设为 0，只取消价格惩罚，不取消范围限制。

### 七、玩家工厂供货：库存门槛决定是否参与

无论“优先从玩家进货”开启还是关闭，均按以下比例判断自有货源是否参与：

```text
该商品库存比例 = 该商品实物库存 ÷ 该商品分配仓储量
```

库存比例必须**严格超过**“玩家工厂存货超过%时允许供货”的设置值。

例如：

| 项目 | 数量 |
|---|---:|
| 该商品分配仓储量 | 10,000 件 |
| 当前库存 | 8,000 件 |
| 供货门槛 | 60% |
| 收货站需求 | 7,000 件 |

当前库存比例为 80%，超过门槛，可以参与供货。这次允许运走 7,000 件，只留下 1,000 件。

**门槛用于判断是否参与供货，不要求运输后仍保留该比例。** 这样，库存较低的销售型工厂可以继续对外销售，积货或专供工厂则参与内部后勤。

自有货源仍须具有合法卖报价和可售数量。开启优先后，可以先选择更远但在允许范围内的玩家货源；关闭后，它与NPC按相同排序规则竞争。关闭优先不会改变实际所有权、免费内部调拨或自有调拨的价差例外。“从AI派系中收集”仍只控制真正的NPC货源。

| 玩家货源状态 | 开启优先 | 关闭优先 |
|---|---|---|
| 库存严格超过门槛，且贸易可执行 | 优先于NPC选择 | 与NPC按相同排序规则竞争 |
| 库存等于或低于门槛 | 不参与 | 不参与 |
| 库存过门槛，但路径、停靠等条件不符 | 跳过，继续寻找其他货源 | 同样跳过 |
| 自有可售数量不足 | 可组合自有采购与NPC采购，仍受最大笔数限制 | 按普通排序组合剩余需求 |

### 八、取消、空闲与余货处理

| 情景 | 处理方式 |
|---|---|
| 玩家取消贸易订单 | 释放相应需求占额，允许其他空闲船重新接单 |
| 船只无法执行采购 | 在对应船的行为失败提示中显示原因 |
| 查看为什么这样采购 | 在对应船的“日志”页保留设置、模式、组合与实际提交结果；价格和偏离范围失败按次数及最小缺口汇总。待命简报10分钟冷却。扩展选项的Debug默认关闭，开启并以 `-scriptlogfiles` 启动后，将候选详情写入文档目录的 `logs/MulesExtended/debug.txt` |
| 单艘 M4 空闲且没有活动或排队命令、未由玩家驾驶 | 独立返回基点站附近或基点星区，其他 M4 忙碌不影响返航 |
| 修改基点星区 | 切换到新基点的需求与货源搜索；无合适贸易时返回新基点，不沿用船所在星区或旧基点。已排队贸易仍完成 |
| 船上有余货，且已无活动或排队订单 | 采用虚拟清仓：删除余货，按商品均价补偿玩家；不视为实际交付 |

## 安装与兼容

从 [Releases 的 v0.1.0-beta.3 页面](https://github.com/Sam-D709/Mules-Supply-Mod-OPUS/releases/tag/v0.1.0-beta.3)下载 **`Mules-Supply-Mod-OPUS-v0.1.0-beta.3.zip`** 安装附件。当前为公开测试版，X4内部版本665。不要误选自动生成的 **Source code** 源码包；本模组不使用 GitHub Packages。后续维护见[版本命名与发布指南](docs/VERSIONING.zh-CN.md)。

1. 退出游戏，备份存档及原模组目录。
2. 解压安装 ZIP，得到 **`mules_and_warehouses_extended`** 文件夹，将整个文件夹拖入 X4 的 **`extensions`** 目录。升级时先把旧模组文件夹移到 `extensions` 以外，再放入新文件夹，避免旧散装文件覆盖新归档。
3. 启动后确认扩展名为 **Mules-Supply-Mod-OPUS**，给船设置 M4 基点和参数。旧船的最大交易次数若仍为 1，需手动调整；旧玩家购买模式不会转换为库存门槛，新门槛默认 50%。

安装后的路径应为：

```text
E:\SteamLibrary\steamapps\common\X4 Foundations\extensions\
└── mules_and_warehouses_extended\
    ├── content.xml
    ├── ext_01.cat
    ├── ext_01.dat
    ├── README.md
    └── README.en.md
```

包内包含中英文说明和界面资源，由游戏语言自动选择；不需要编译或另装语言文件。`SHA256SUMS.txt` 附件可用于核对下载完整性。

本项目保留原扩展 ID 以兼容已有订单，**不能与原骡子模组并行安装**。Steam 创意工坊更新可能覆盖原目录。M4 依据空间站买报价补货，不修改游戏的自动仓储、自动定价或研究需求判定。
