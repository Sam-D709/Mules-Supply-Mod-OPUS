# Mules-Supply-Mod-OPUS

面向 **X4: Foundations** 的供应优化模组，基于 **Mules, Supply and Warehouses Extended 6.60**，主要重写 **M4 采购骡子**：按真实货仓容量分配任务，多笔采购合并运输，小额缺货也能补齐。M1、M2、M3 保留。

## M4 参数对照

以下“原版”指骡子模组 6.60。参数名称采用其中文界面名称；新版数值为新建行为的默认值，已有船的设置可能保留。

| 原版参数 | 新版参数与设置 | 为什么修改 |
|---|---|---|
| 最大交易次数：固定 1 笔 | 同名；**默认 3 笔，可设 1～10 笔** | 允许把多个小需求拼成一趟，提高装载率；同时限制笔数，避免一艘船包揽全部小单、其他船闲置。一个货源的一种商品送给一个收货对象算一笔，交付不另算。 |
| 货仓装载 %：25～95%，默认 75% | 同名；**0～95%，默认 75%**，判断整趟采购的合计装载率 | 副单可以很小，只要整趟满足比例。剩余小单另由尾单机制处理，不让“只缺 1 件”长期无法补货。 |
| 从玩家收集 | **启用从玩家工厂进货**；默认开启 | 明确这是货源权限开关，与 NPC 货源开关独立控制。 |
| 玩家购买模式：自有卖价的判断倍率，0～100%，默认 100% | 删除，改为 **玩家工厂存货超过%时允许供货**；0～100%，默认 50% | 用库存区分销售与后勤：库存低的自有工厂继续对外赚钱，积货或专供工厂参与供货，不再用难理解的价格倍率表达意图。 |
| 评估的交易 %：5～100%，默认 100% | **删除可见参数**，由调度器完整检查候选并分批计算 | 玩家无需调节搜索强度；通过共享搜索结果和分批让出计算，减少重复工作。 |
| 允许建材 | **为建造仓采购材料**；默认开启 | 说明是把材料送入收货站的建造仓，用于新建或扩建。 |
| 允许原材料 | **采购本站不生产的消耗物资**；默认开启 | 分类以收货站用途为准，例如电子设备厂需要的微芯片，并不只指矿石和气体。 |
| 允许中间产物 | **采购本站自产自用的物资**；默认开启 | 综合工厂内部产量不足时，可以从外部补充它既生产又消耗的物资。 |
| 允许商品 | **删除可见开关**，纯贸易库存按合法买报价补货 | 玩家已在空间站设置买报价，就不需要再开启一个含义模糊的商品选项；仍保留原有的最终产品特殊过滤。 |
| 仅服务基点空间站/星区 | **仅给基点空间站/星区补货**；默认关闭 | 明确限制的是送货对象：开启时，站基点只服务该站及其建造仓，星区基点服务该星区玩家站；货源仍可位于活动范围内其他星区。 |
| 无 | **副单离主路径范围（跳）**；0～10 跳，默认 2 跳 | 允许沿主单路线拼单，但限制绕路距离；同时保留基点最大活动范围限制。 |
| 无 | **副单偏离每跳估价加成 %**；0～50%，默认 5% | 同商品有多个货源时，用价格加成体现绕路成本，只影响选择，不改变实际付款。 |
| 基点 空间站/星区、分配到空间站下属、最大活动范围 | **保留** | 沿用基点和范围设置，修正站属绑定问题；分配为空间站下属需要选择具体玩家空间站。 |
| 从 AI 派系中收集、锁定自定义商品列表、商品（默认全部） | **保留** | 继续控制 NPC 货源权限，以及允许采购的商品范围。 |

## 这些参数如何配合

**先按容量派单，再补小额尾单。** 同一基点共用需求与货源信息，船按实际货仓容量排序，不按 XL/L/M/S 判断大小。正常阶段从大容量船向小容量船分配，最多组合设定笔数，检查整趟装载率；剩余需求再从小到大逐级豁免装载率。小船忙碌后，中船、大船也能接尾单，不会永远等小船。豁免不放宽交易笔数、距离、预算、停靠、无人机或贸易规则。

**主单优先近，副单控制绕路。** 主单货源先比较距基点的合法星区跳数，同跳数再比较实际采购价格（含可取得的优惠）。主单确定后，固定“基点→主单货源”路径。副单同商品货源的竞争估价为 `实际单价 ×（1 + 偏离跳数 × 每跳加成%）`。例如路径内报价 103，偏离一跳报价 100、加成 5%，后者估价为 105，因此选 103；只有那个偏离货源时，它仍可入选。加成设 0 也不会取消范围限制。

**自有库存门槛不是保留库存。** 判断的是“该商品实物库存 ÷ 该商品分配仓储量”，严格超过门槛才参与。比如分配 10,000、库存 8,000、门槛 60%，目的地需要 7,000，可以运走 7,000，不必留下 60%。仍须有合法卖报价和可售数量；合格自有调拨不要求正买卖价差，也不强制优先选择更远的自有工厂。

此外，取消订单后可重新派单；无法贸易的原因会显示到对应船的行为失败提示中；同一基点 M4 全部空闲时返回基点站附近或基点星区。没有活动或排队订单时，余货按原骡子的虚拟清仓方式删除并以商品均价补偿玩家。

## 安装与兼容

1. 退出游戏，备份存档及原模组目录。
2. 将包含 `content.xml` 的模组目录安装为 `extensions/mules_and_warehouses_extended/`，替换原骡子模组。使用散装源码安装时，移走旧 `ext_01.cat` / `ext_01.dat`。
3. 启动后确认扩展名为 **Mules-Supply-Mod-OPUS**，给船设置 M4 基点和参数。旧船的最大交易次数若仍为 1，需手动调整；旧玩家购买模式不会转换为库存门槛，新门槛默认 50%。

本项目保留原扩展 ID 以兼容已有订单，**不能与原骡子模组并行安装**。Steam 创意工坊更新可能覆盖原目录。M4 依据空间站买报价补货，不修改游戏的自动仓储、自动定价或研究需求判定。
