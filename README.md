**简体中文** | [English](README.en.md)

面向 **X4: Foundations** 的供应优化模组，基于 **Mules, Supply and Warehouses Extended 6.60**，主要重写 **M4 采购骡子**：逐船独立分配任务，按实际可运体积与航程比较方案，多笔采购合并运输，小额缺货也能补齐。M1、M2、M3 保留。
目前仅在X4 Version 8.00 Hotfix 4 (legacy) + SWI星球大战模组中进行测试，至于原版 8.0 与 9.0 并未做测试，如果有任何适配性问题欢迎提出Issue

## M4 参数对照

以下“原版”指骡子模组 6.60。参数名称采用其中文界面名称；新版数值为新建行为的默认值，已有船的设置可能保留。

| 原版参数 | 新版参数与设置 | 为什么修改 |
|---|---|---|
| 最大交易次数：固定 1 笔 | **每趟最多采购笔数**；默认3，可设1～10 | 同种商品多厂采购或不同商品拼单，均分别计数；每趟先采购后交付 |
| 货仓装载 %：25～95%，默认 75% | 同名；**0～95%，默认 75%**，判断整趟采购的合计装载率 | 主要订单和所有次要订单占货仓合大于此值，即可进行交易 |
| 从玩家收集 | **删除可见参数**；旧存档值忽略 | 合格玩家与NPC货源按相同货量、距离和整趟效率比较，无所有权奖励。 |
| 玩家购买模式及后续玩家库存百分比门槛 | **删除可见参数**；旧值忽略 | 玩家与NPC一样使用原生合法可售量。保留库存请在工厂货物出售设置中控制。 |
| 评估的交易 %：5～100%，默认 100% | **删除可见参数**，由调度器有限搜索并分批计算 | 此参数原本决定搜索订单的频率，但我认为其对于性能的影响非常小，没有必要展现 |
| 允许建材 | **为建造仓采购材料**；默认开启 | 变更中文翻译，其可以为建材仓库贸易 |
| 允许原材料 | **采购本站不生产的消耗物资**；默认开启 | 即该工厂原材料不足时对原材料进行贸易 |
| 允许中间产物 | **采购本站自产自用的物资**；默认开启 | 即该工厂中间产物不足时对中间产物进行贸易 |
| 允许商品 | **删除可见开关**，纯贸易库存按合法买报价补货 | 个人认为该参数没有任何存在的必要，因为启用仓库贸易本身就会放出收购表，飞船完全可以根据该收购表进货 |
| 仅服务基点空间站/星区 | **仅给基点空间站/星区补货**；默认关闭 | 基点选择为某空间站时：关闭该参数，为该星区其他玩家空间站贸易，开启时只为该空间站贸易，，，基点选择为某星区时：关闭该参数为其他邻接星区玩家的空间站进行贸易，开启时只为该星区玩家所有空间站进行贸易 |
| 无 | **副单离主路径范围（跳）**；0～10 跳，默认 2 跳 | 距离主要订单路径星区多少范围的星区内寻找次要订单 |
| 无 | **副单偏离每跳估价加成 %**；0～50%，默认5% | 同等级方案的累计成本比较使用偏离加成；运量/预计用时优先，不修改实际付款 |
| 基点 空间站/星区、分配到空间站下属、最大活动范围 | **保留** | 是否分配到具体空间站下属作为贸易商？ |
| 从 AI 派系中收集 | **删除可见参数**；旧值忽略 | 自动考虑合格NPC货源；仍遵守游戏原生贸易权限与黑名单。 |
| 锁定自定义商品列表、商品（默认全部） | **保留** | 控制允许采购的商品。 |

## 详细算法介绍

每艘空闲 M4 独立找单，使用同一基点共享的需求和货源索引。船型和货仓容量影响能装多少、能否满足装载率，不再规定大船先处理完、小船才能接单。谁先完成合法方案并成功提交，谁取得相应数量。

### beta.7 分级与限额修复

主单按兼容空闲船的实际仓容分档，档内最大/最小不超过1.5倍。使用本船合法候选的净需求/净供货估算体积，同收货对象、同仓型可组合供大船处理；副单跨档补舱。等待90游戏秒或3轮未获任务后允许跨档主单，不设全船队先大后小屏障。分级在放宽前会阻止不匹配货量作为主单；其判断其他船的条件并不等于逐笔交易资格，当前策略尚待进一步讨论。最终资格与路线仍逐船验证。

未获任务满2/5/10游戏分钟时，有效装载率上限分别降为50%/25%/0%；原设置更低时沿用原设置，三次完整装载失败仍可提前豁免。只成功派单或更换配置才重置等待起点，预算耗尽和返航不重置。

净供需缩水后仅修复一次，按最新数量重建原单，从已有候选额外检查最多12个、补最多2笔，再通过有效装载率与全部最终复核。不会为修复重新发现全宇宙报价。共享粗筛只保存基点/商品的原始货量、距离、报价排序，30游戏秒到期或发现变化时更新；个人资格和失败不共享。

返航的30秒信号改为调用专用优先级1的poll脚本，保留无任务时的移动栈；原生遇袭响应优先级10仍可阻止本次搜索，随后信号继续重试。详见[beta.7说明](docs/releases/v0.1.0-beta.7.md)。

### 货量与航程怎样取舍

采购数量来自实际可用卖报价，而非工厂全部实物库存：先扣除原生预订尚未接管的模组占额，再限制于净需求、船仓、收货仓、双方资金和最小交易量。货物体积使用游戏的 `ware.volume`，运量为 `数量 × 单件体积`。

对每种商品，保留货量大、距基点近、原始报价低的少量货源，以及轮换候选。实际船只资格、优惠和净数量只对这些候选检查。失败后扩大候选并轮换，避免永远盯住同一批不适用工厂。

主单可以替换，不由最近一家少量补产的工厂永久决定。尝试有限的主单与多笔组合，先判断是否达到最低装载率，随后比较：

```text
方案效率 = 整趟实际可交付体积 / 预计整趟耗时
预计耗时 = 船当前位置→各采购点→收货站的合法跳数权重 + 每次装卸权重
```

当前按 S/M 每跳90、每次装卸45，L/XL 每跳180、每次装卸120估算相对时间。评分存为 `floor(体积×1000000/时间权重)`，先使用64位整数放大再除；日志score除以1000000才是原单位。这是调度启发值，不是游戏原生ETA；尚不含星区内距离、拥堵、实际航速或真实泊位等待。相同等级的方案再以累计实际价格和偏离加成成本比较。

| 情况 | 预期取舍 |
|---|---|
| 最近工厂只有10件，稍远工厂能装满 | 少量货源不会自动锁定主单；比较更完整的方案 |
| 附近能装80%，远处能装100%，门槛75% | 两者都可出发，再按预计单位时间运量比较；不强求满载 |
| 两种需求分别只能装40% | 同收货对象、同仓型、路径允许时可组合为80% |
| 同种商品分散在两家工厂 | 可以分别采购，分别计入最大采购笔数 |
| 价格更低但明显绕远 | 折扣不自动压过运输效率，预算和价差仍必须合法 |

### 多单与有限搜索

每趟服务一个收货对象、使用一种兼容仓型，先全部采购再交付。基点/本星区/扩展范围以及建造仓/消耗/自产自用/贸易库存仍有优先层级；副单可组合其他允许用途的货物。每个主单方案都有独立的“基点→主货源”固定走廊，副单不得突破走廊或基点最大范围。

每次最多192次需求与货源配对检查、128次路线扩展；每个状态最多选择6个扩展候选、保留3个方案。达到上限后继续轮换需求和货源，下一次再找，不把搜索不完整计为装载不足。候选筛选额度与路线扩展额度独立：筛选耗尽仍可用已找到的候选拼单。组合前刷新净供需，每次有限扩展再次读取净数量，减少搜索让出后沿用旧满仓数量的情况；最终提交仍复核。这是有限搜索，不保证全局最优；最大采购笔数是上限，不要求每次凑满。

### 三次装载不足后放宽

本船连续三次**完整搜索**只有低于最低装载率的方案，第四次搜索临时豁免装载率。价格、权限等其他失败会打断连续计数；计算额度耗尽不增加计数。成功或更换配置后重置。只放宽装载率，资金、报价、路径、仓容、无人机和最大采购笔数仍有效。

### 共享索引与短提交锁

先在共享发现阶段排除不属于服务对象的NPC买单。新发现报价可增量加入索引，另有30游戏秒刷新；刷新期间发生新增报价会要求后续重建。各船搜索可交错运行。

全局互斥只保护最后的净数量复核、占额及订单创建，临界区及其助手均使用非阻塞动作库；不覆盖发现报价、规划路线或整支船队。提交前重新读取实际价格，变化后只要仍符合预算和价差就可提交，避免自有站报价变化让合法运输反复作废。

### 玩家工厂可售量

玩家货源不再检查模组自设库存百分比或分配仓储量。是否出售、保留多少货物，由工厂原生出售设置及实际卖报价决定；M4仍检查净可售量、预订、资金和交易资格。旧库存门槛与自有优先值均被忽略，NPC货源许可开关也已移除，旧关闭值忽略。

## 取消、空闲与余货处理

| 情景 | 处理方式 |
|---|---|
| 玩家取消贸易订单 | 释放相应需求占额，允许其他空闲船重新接单 |
| 船只无法执行采购 | 在对应船的行为失败提示中显示原因 |
| 查看为什么这样采购 | 在对应船的“日志”页先显示最终结果及具体失败原因，再显示组合和真实副单尝试。失败按原因类别10分钟冷却；类别变化立即显示，成功始终记录。扩展选项的Debug默认关闭，开启并以 `-scriptlogfiles` 启动后，将候选详情写入文档目录的 `logs/MulesExtended/debug.txt` |
| 单艘 M4 空闲且没有活动或排队命令、未由玩家驾驶 | 独立返回基点站附近或基点星区，其他 M4 忙碌不影响返航 |
| 修改基点星区 | 切换到新基点的需求与货源搜索；无合适贸易时返回新基点，不沿用船所在星区或旧基点。已排队贸易仍完成 |
| 船上有余货，且已无活动或排队订单 | 采用虚拟清仓：删除余货，按商品均价补偿玩家；不视为实际交付 |

## 安装与兼容

当前测试版安装包为 `dist/Mules-Supply-Mod-OPUS-v0.1.0-beta.20.zip`，内部版本682，从 [v0.1.0-beta.20 Release](https://github.com/Sam-D709/Mules-Supply-Mod-OPUS/releases/tag/v0.1.0-beta.20) 下载。后续维护见[版本命名指南](docs/VERSIONING.zh-CN.md)。

1. 退出游戏，备份存档及原模组目录。
2. 解压安装 ZIP，得到 **`mules_supply_mod_opus`** 文件夹，将整个文件夹拖入 X4 的 **`extensions`** 目录。升级时先把旧模组文件夹移到 `extensions` 以外，再放入新文件夹，避免旧散装文件覆盖新归档。
3. 启动后确认扩展名为 **Mules-Supply-Mod-OPUS**，给船设置 M4 基点和参数。旧船的最大交易次数若仍为 1，需手动调整；旧玩家购买模式、自有优先和库存门槛不再生效；供货保留量请在工厂出售设置中调整。

安装后的路径应为：

```text
E:\SteamLibrary\steamapps\common\X4 Foundations\extensions\
└── mules_supply_mod_opus\
    ├── content.xml
    ├── ext_01.cat
    ├── ext_01.dat
    ├── README.md
    └── README.en.md
```

包内包含中英文说明和界面资源，由游戏语言自动选择；不需要编译或另装语言文件。`SHA256SUMS.txt` 附件可用于核对下载完整性。

本项目使用独立扩展 ID `mules_supply_mod_opus` 和同名目录，不再使用原版创意工坊标识。**升级旧版时，先将 `extensions/mules_and_warehouses_extended` 移到游戏扩展目录之外，再安装新目录；不要复制回原版目录。请退订或在游戏中禁用原版骡子，两个版本不能同时启用。** 原版与本版仍有同名脚本和行为。旧存档请先备份；首次加载确认本版已启用，必要时重新选择M4行为。M4 依据空间站买报价补货，不修改游戏的自动仓储、自动定价或研究需求判定。

## 提交bug

安装 SirNukes Mod Support APIs，在模组管理菜单打开 Mules-Supply-Mod-OPUS 的 Debug 开关，然后复现问题。将 `Documents\Egosoft\X4\<用户编号>\logs\MulesExtended` 中的日志压缩后提交；存档位于同一用户目录的 `save`。尽量提供复现前正常存档和复现后异常存档；存档过大时可尝试新档复现。beta.8起请提供四个完整的 `m4-*.txt` 文件。

## 已知限制

路线耗时为跳数和装卸权重估计，有限候选可能漏掉更好的组合；失败后轮换降低长期遗漏。NPC可以建立新厂，但只能使用游戏中已获知且允许本船交易的报价；报价更新不等于每帧扫描全宇宙。SETA会加速游戏时间，也会增加同一现实秒内需要完成的工作，本次不承诺特定FPS。
